# Spring 트랜잭션 처리방식 비교

트랜잭션에 대해 공부하던 중, 회사에서 사용 중인 프레임워크를 살펴보니 트랜잭션 처리가 XML 기반 AOP 방식으로 구성되어 있었다.
반면, 최근의 프로젝트에서는 @Transactional 어노테이션 방식을 기본으로 사용하는 것이 일반적이다.

이 두 방식이 어떻게 다르고, 왜 회사 프로젝트에서는 XML 기반 방식을 선택했는지 정리해보았다.


## XML기반 AOP vs @Transactional

우선 두 방식은 동작 원리 자체는 동일하다.
모두 내부적으로 Spring AOP + PlatformTransactionManager를 기반으로 트랜잭션을 처리한다.

차이점은 트랜잭션을 선언하고 관리하는 방식에 있다.

- @Transactional 방식은 메서드 또는 클래스 단위로 어노테이션을 선언하여 개별 비즈니스 로직 중심으로 트랜잭션을 적용한다.

- XML 기반 AOP 트랜잭션 방식은 XML 설정 파일에서 트랜잭션 정책을 일괄 정의하고, pointcut 조건을 통해 트랜잭션을 적용할 대상 메서드를 지정한다.


## 회사 프로젝트의 트랜잭션 설정 방식
우리 회사 프로젝트의 경우 *Impl 형식의 이름을 가진 클래스의 모든 메서드에 트랜잭션이 적용되도록 설정되어 있었다.

이는 트랜잭션에 대한 이해가 부족한 초보 개발자라도 별도의 설정 없이 안정적인 개발이 가능하도록 하기 위한 설계라고 판단된다.

즉, 서비스 계층 전체에 트랜잭션을 자동 적용하고 개발자는 비즈니스 로직에만 집중할 수 있도록 한 것이다.

다만, 메서드별로 트랜잭션 범위를 세밀하게 제어하기는 어렵고 코드만 보아서는 트랜잭션 적용 여부를 직관적으로 파악하기 힘들다는 단점도 존재한다.
