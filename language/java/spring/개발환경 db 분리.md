# 왜 개발용으로는 H2 DB를 사용하는가?
- DB를 설치할 필요가 없음
- 서버를 띄우면 바로 DB생성
- 테스트 & 디버깅 시 편함
    - /h2-console에서 바로 SQL 확인가능
- Spring Boot + JPA를 쓴 경우 H2 에서 다른 DB로 바꿀 때 코드수정이 거의 없다

## H2를 쓰면 매번 기초데이터(유저 등)을 넣어야해서 불편하지 않을까?
- 초기데이터 스크립트를 만들어 두면 된다.

## 실무 예시
- 로컬 개발: H2, 로컬 MySQL, Docker DB 등
- 공용 개발서버: 개발용 DB
- 스테이징: 운영과 거의 동일
- 운영: 운영 DB

현재 회사는 로컬개발 시 개발용 공용DB에 연결해서 쓰고있다. 로컬 DB와 개발서버 DB가 분리되지 않은 경우 테스트중인 불완전한 데이터로 테스트를 하게되어 올바른 테스트가 되지 않고 운영과 환경이 다르니 잠재적인 버그요인이 될 것 같다.
