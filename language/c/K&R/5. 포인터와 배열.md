# Chapter5. 포인터와 배열

## 5.1 포인터와 주소

> 포인터: 다른변수의 주소를 그 값으로 가지는 변수

- 포인터는 배열과 밀접한 관계를 가짐.

> &: 번지를 알아내는 연산자
> p=&c

&: 일반변수에 쓰는 것
\*: 포인터 변수에 쓰는것 그 주소로 찾아가게 함

`int *ip;` : 정수형 변수의 포인터 선언
`ip = &x` : \*ip는 x대신 사용가능함.

### 연산자 우선순위

\* 와 후위연산자 ++

- 후위연산자 ++ 가 \*보다 우선순위가 훨씬 높다.
- \*p++는 \*(p++)와 같이 계산된다.

\* 와 전위연산자 ++

- 둘은 우선순위가 같다.
- 변수에 가까운것 부터 실행된다.
- \*++p : ++가 먼저 실행
- ++*p : *가 먼저 실행

## 5.2 포인터와 함수의 매개변수

- 포인터를 이용하면 함수안에서 변수에 직접 접근 가능함.

```
swap(&a, &b);

void swap(int *px, int *py)
{
  int temp;

  temp = *px;
  *px = *py;
  *py = temp;
}
```

## 5.5 문자 포인터와 함수

문자열 상수 printf("Hello, world\n");

```
printf("hello, world\n");
printf("hello, world\n");
```

동일 문자열을 두번 출력한 경우: 컴파일러마다 다를 수 있으나, 대부분의 경우 동일한 주소값을 가짐.

문자열은 컴파일 시에 메모리에 할당된다.

```
char amessage[] = "now is the time"; /* an array */
char *pmessage = "now is the time";
```

둘 다 같은 문자열이지만 저장되는 메모리 영역은 다르다.
`amessage`: 스택(Stack)영역, 수정가능함
`pmessage`: 문자열 값은 ROData(Read-Only Data, 상수) 영역에 저장되고 pmessage변수는 스택영역에 저장

- `pmessage[0] = 'N'` 과 같이 상수영역의 메모리를 수정하려고 하면 프로그램 즉시 다운됨.

### 상수영역은 스택영역보다 RAM영역을 아낄 수 있다.

- ROM (Flash 메모리): 용량이 크고 저렴
- RAM: 용량이 작고 비쌈

`pmessage`방식을 쓰면 ROM의 읽기전용 상수영역에 딱 한번 저장됨. 필요할 때 마다 포인터로 ROM의 글자를 읽어옴.

> 성능상에 문제가 없을까?
> 성능문제가 거의 없거나, 오히려 이 방식이 유리함.
> 배열방식도 결국 ROM에 접근해야하고
> ROM접근 시 캐시메모리, ART가속시 등을 써서 손실 최소화 가능함

ROM에 빠르게 접근 가능하다면 왜 RAM을 쓰는걸까?
RAM과 ROM은 `값 쓰기` 방식에 엄청난 차이가 있다.

- RAM은 특정 메모리 주소의 값을 바꾸는 비용이 아주 작음. 무한히 값 변경 가능
- ROM은 "1바이트만 골라서 지우고 다시 쓰기" 불가능. 값을 바꾸려면 수 KB단위의 '섹터/블록' 전체를 통째로 지우고 다시써야함. 각 구역당 1만~10만번 지우고 쓰면 그 구역이 물리적으로 망가짐.

## 5.6 포인터 배열: 포인터의 포인터

> 뒷 글자가 진짜 정체다!

### 포인터 배열과 배열 포인터

- 포인터 배열: '배열'임 (Array of Pointers)
  - 여러 포인터들을 저장해둔 배열 `int *arr[3]`
- 배열 포인터: '포인터'임 (Pointer to an Array)
  - 특정 배열을 가리키는 포인터 `int (*ptr)[3]`: 가로크기가 3인 int배열을 가리키는 포인터
  - +1 연산 시 3칸(1칸=4바이트)씩 건너뜀

선언방법
`int *arr[3];`

사용용도: **크기가 제각각인** 하드웨어 버퍼나 문자열들을 묶어서 관리

```
// 문자열 상수의 주소 3개를 모아놓은 포인터 배열
char *error_messages[3] = {
    "OK",                  // [0] -> 'O', 'K', '\0'이 있는 주소
    "WARNING_LOW_BATTERY", // [1] -> 긴 문자열이 있는 주소
    "CRITICAL_OVERHEAT"    // [2] -> 다른 문자열이 있는 주소
};
```

### 포인터 연산의 기준

포인터 연산(+1) 시 몇 칸을 건너뛸지 기준은
**이 포인터 변수가 처음에 어떤 타입으로 정의되었는가?** 이다.

```
int z[10];
int *ip;
ip = &z[0]; -> 4바이트씩 건너뜀

int (*ap)[10];
ap = &z; -> 40바이트씩 건너뜀
// ap = &z[0] -> 타입이 달라서 안됨. 포인터 연산상의 오류를 막기 위해. 무조건 길이가 10인 배열의 포인터가 와야함.
```

## 5.7 다차원 배열

> 핵심 진실: 컴퓨터 메모리는 언제나 '1차원'이다.

- C언어는 행 중심 순서로 데이터를 저장함
  - 0번째 행 먼저 저장 -> 1번째 행 저장..
  - 2차원 배열은 메모리 공간에 빈 틈 없이 한 줄로 늘어서 있음

### 다차원 배열의 메모리 저장

다차원 배열은 아무리 사이즈가 크더라도, 연속된 단 하나의 메모리 공간을 찾아서 할당함

배열의 값에 접근할 때 컴퓨터 내부에서는

> 물리 주소 = 배열의 시작 주소 + (500 _ 1000 + 200) _ 4바이트
> 식으로 물리주소를 계산함.

배열이 파편화되어 저장되어있다면 위 공식은 사용불가능함.

임베디드 실무에서 큰 데이터를 다루는 방법

- 포인터 배열을 이용한 '인위적 쪼개기' (행별 동적 할당)
- 임베디드 리눅스와 같은 MMU(Memory Management Unit)라는 하드웨어 탑재의 경우
  - malloc(10MB)로 거대한 2차원 배열을 잡아도, 내부 하드웨어가 알아서 물리 메모리를 쪼개서 맵핑함 (가상메모리)
- MMU가 없는 하위 제어기(Cortex-M, MCU, 펌웨어 환경): 가상 메모리가 없어서 100% 물리메모리 그대로 연속되어야 함
- 따라서 임베디드 리눅스 개발자는 펌웨어 개발자에 비해 대용량 배열을 다룰 때 메모리 파편화를 덜 신경써도 됨

### 다차원 배열의 전달

매개변수로 다차원 배열을 전달하면 첫 번째 행 배열의 포인터만 전달함. 행의 사이즈는 전달하지 않음.
행의 사이즈를 모르는데 Array Overflow각 발생하지 않을까?

> 발생한다! C는 속도를 위해 안전장치를 최소화 하였음.
> 따라서 반드시 행의 크기를 별도 변수로 넘겨주는 습관을 들이자.
