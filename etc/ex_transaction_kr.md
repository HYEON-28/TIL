# 트랜잭션 관련 버그(2026.01.22)

오늘 고객에게서 생산마감 기능이 작동하지 않는다는 연락이 왔다. 개발을 담당한 담당자(부하직원)에게 바로 확인요청을 하고, 나도 원인을 파악하기 시작했다. 내가 마감을 시도하니 마감테이블에서는 중복키 오류가 뜬다. 이미 마감 테이블에는 데이터가 존재하는 상태였다. 즉, 생산 마감 자체는 처리되었지만,
공정별 작업 중인 생산지시번호 테이블이 함께 업데이트되지 않아
시스템 상에서는 여전히 해당 공정이 작업 중으로 인식되고 있었다.
이로 인해 재마감을 시도하면서 마감 테이블에서 중복 키 오류가 발생한 것이다.

위 생산마감과 생산지시번호 테이블 업데이트 쿼리는 하나의 트랜잭션으로 묶여있어야 하는데 담당자가 이 사실을 간과하고 두개의 별도 API를 만들어 프론트에서 호출하는 식으로 구현해 두었던 것이다. (우리 백엔드는 Spring 기반으로, 
Service 계층 단위로 트랜잭션을 관리하고 있어
하나의 API 내부에서는 트랜잭션이 보장되는 구조다.) 그래서 이렇게 데이터가 꼬이는 상황이 발생을 했다. 

트랜잭션은 로직을 실행하는 중간에 문제가 생긴 경우 전체 로직을 롤백시키는 역할을 한다. 모두 실행하거나, 모두 실행하지 않거나(ALL-OR-NOTHING) 인것이다. 이와 같은 ALL-OR-NOTHING 전략은 생산 시 입고와 출고를 동시에 처리하는 경우나, 금융 시스템에서 송금 시 출금과 입금을 함께 처리하는 경우처럼 하나라도 실패하면 전체가 취소되어야 하는 로직에서 필수적이다.

프로그램이 오류없이 돌아가면 문제가 없지만 만에하나 오류가 생긴 경우 트랜잭션이 없다면 데이터가 다 꼬여버린다. 코드수정에 틀어진 데이터수정까지 해줘야한다. 코드 수정은 원인을 찾으면 비교적 단순히 해결할 수 있지만, 트랜잭션이 깨져 발생한 데이터 오류는 하나의 테이블에 국한되지 않는다. 연관된 여러 데이터가 함께 틀어지기 때문에
어디서부터 어떻게 복구해야 할지 판단하기조차 어려운, 훨씬 큰 장애로 이어질 수 있다.
