# Docker 기본 정리

애플리케이션과 실행 환경(라이브러리, 설정 등)을 하나의 **컨테이너**로 묶어 어디서든 동일하게 실행할 수 있게 해주는 도구.
AWS 같은 클라우드 환경이 아닌 온프레미스에서도 충분히 사용 가능.

## 궁금했던 점

> 도커를 사용하면 기존 OS 위에 가상 OS를 올리는 거니까 성능이 떨어지지 않을까?

→ 가상 OS가 아니라 호스트 OS의 커널을 **공유**하는 방식이다. 성능 손실은 1~3% 수준으로 체감상 거의 없다.

## 특징

- 마이크로서비스 구조에 적합
- VM보다 속도가 빠르고 용량이 작음
- 컨테이너 단위로 환경이 격리되어 있어 "내 컴퓨터에선 됐는데" 문제가 줄어듦

## 동작 흐름

1. Dockerfile 작성
2. `docker build`
3. Image 생성
4. `docker run`
5. Container 실행

## 용어 정리

| 용어       | 설명                           |
| ---------- | ------------------------------ |
| 이미지     | 컨테이너를 만들기 위한 설계도  |
| Dockerfile | 이미지를 만들기 위한 설정 파일 |
| 컨테이너   | 이미지를 실행한 인스턴스       |

- [ ] 실무 적용 (Mac 개발환경)

1. Docker Desktop 설치
2. 설치 확인

   ```bash
   docker --version
   ```

3. `docker-compose.yml` 작성
   - `version: '3'`은 compose 문법 버전. 3이 가장 안정되고 많이 쓰임 (필수는 아님)
